# ADM-001.2 — Cadastro e gestão central de oficinas (etapa administrativa)

## Escopo entregue

O painel central permite pesquisar e paginar oficinas, consultar os dados cadastrais e o histórico de auditoria, cadastrar uma oficina fictícia ou real autorizada por um administrador principal e editar nome, responsável, e-mail, telefone e documento. Mudanças manuais podem colocar um cadastro gerenciado em somente leitura, bloqueado ou arquivado, sempre com justificativa. O backend valida a permissão `workshops:read` ou `workshops:manage`; IDs e `tenant_id` vindos do navegador não concedem autorização.

Os cadastros anteriores aparecem como `legacy`. A migração não muda o acesso nem cria dados para essas oficinas. O painel administrativo não recebe acesso de leitura às tabelas operacionais. A migração aditiva cria o registro central e uma linha mínima de tenant para novos cadastros, mas não cria usuários, clientes, ordens, cobrança ou assinatura. Cadastros criados ficam `pending_verification` e não podem autenticar no sistema operacional. Oficinas em estado `trial` com prazo encerrado passam automaticamente a somente leitura; somente workflows de confirmação/cobrança futuros poderão liberar teste, ativação e tolerância.

## Preparação local

Use somente o PostgreSQL local `horse_power_local` e o `.env.local` já configurado para loopback:

```powershell
npm.cmd run db:local:migrate
npm.cmd run dev:admin
```

Em outro terminal, inicie a aplicação em `http://127.0.0.1:5173/admin`. A migração `007-platform-workshops.sql` é aditiva. O runner verifica checksums e para se uma migração já aplicada tiver sido editada. Ela adiciona a tabela `platform_admin.workshops`, uma coluna de ligação de auditoria, funções com privilégios restritos e permissões explícitas. A conta `hp_platform_admin_app` recebe execução das funções administrativas, mas não `USAGE` dos schemas operacionais. `hp_local_app` recebe apenas execução da função de consulta de estado.

Entre com a conta administrativa local configurada pelo procedimento ADM-001.1.1 e use a aba **Oficinas**. Para cadastrar, informe nome, responsável, e-mail, telefone opcional e CPF/CNPJ válido opcional. Não são enviados e-mails nesta etapa: o cadastro permanece pendente, sem login operacional. Edite os dados ou registre mudança de estado na página de detalhes; cada ação gera evento imutável na auditoria.

## Etapas seguintes e limites

O autocadastro público, captura local de e-mails, confirmação de endereço, início e expiração do teste, recuperação de acesso, planos, cobrança e ativação da assinatura permanecem para uma etapa posterior. Não existe envio de e-mail nem conta operacional para as oficinas cadastradas nesta etapa. A interface pode mostrar os estados; o servidor é a autoridade e mantém o acesso legado das oficinas anteriores.

Os testes PostgreSQL usam registros totalmente fictícios e transações revertidas. Nenhum dado real de oficina deve ser usado nos testes. Não use URLs remotas, não configure Vercel e não publique esta etapa sem finalizar o fluxo de confirmação e o ciclo de estados.
